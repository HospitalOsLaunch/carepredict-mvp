## Data interface, source provenance and the unresolved real adapter

\`research_lab.synthetic_adapter_v1.build_window\` is a **stdlib-only**, development-only adapter for the \`integrated_full_model_v1\` data contract. It accepts:

1. **Hospital-level versioned observations**, preserving the \`OPERATIONAL_V2_RESEARCH_1\` schema, from \`src/hospitalos/operational/adapter.py\`.
2. **A separately materialized, same-run synthetic action ledger**, schema \`hospitalos.synthetic_action_ledger_v1\`, with exactly \`staffing_delta\` and \`discharge_delta\` in existing \`rs_jepa.synthetic.ACTION_COLUMNS\` order.
3. **Versioned topology** (at least one hospital node with declared nominal bed capacity), available at the forecast origin D.
4. Frozen \`integrated_full_model_v1\` spec, explicit decision origin D, later label cutoff L, train/development partition and maximum staleness (hours).

\`research_lab.synthetic_adapter_v1_files.read_sources\` checks independent SHA-256 of the observed gzip, topology and action gzip, then matching underlying source-manifest hashes, source clock, partition, and hospital entity. An identical \`source_manifest_sha256\` on two signed data manifests is an assertion of **common synthetic provenance**, not mathematical proof that the event sets correspond perfectly. A reviewer must also approve the action exporter and check unit/interval alignment.

**Critical missing piece:** the repository’s existing operational adapter exports **observations only**. Its data is \`synthetic_only\`. No same-run \`synthetic_action_ledger_v1\` exporter is claimed to exist yet. The separate RS-JEPA Phase-A synthetic generator produces \`staffing_delta/discharge_delta\` but **is a different simulator/interface**. Combining its actions with observation streams generated by a different hospital world is forbidden. Until an approved synthetic action exporter preserves causal alignment and data identities in the *same run*, archive-based runs must **fail closed**, not use fabricated rows.

## Time semantics

Given D, history C and step Δ, the historical grid is:

\`[D-(C-1)Δ, ..., D-Δ, D]\`.

For each time gridpoint t, select the latest **actual observed event** with \`event_time <= t\` whose record version \`available_at <= D\`, within the explicit max-age cutoff. The newest version is selected only among versions available by D. The observation's value can be \`None\`: then the feature is marked missing, **not** backfilled from a previous version or treated as an actual zero.

Each metric must have three ordered features: measured value, missingness mask (1 = missing), age in hours. Numeric filler zero for an absent value is admissible only because its separate mask is 1. Any inconsistent or hidden-source feature is rejected.

\`event_ns\` and \`available_ns\` hold UTC nanosecond timestamps of the selected source observation (or the gridpoint if missing); \`origin_ns\` is D. They satisfy \`event_ns <= available_ns <= origin_ns\`, but the upstream event-version provenance is the actual protection against revisions and missing/late receipt. This is **historical reconstruction with information known at D**, not a claim that the information was known contemporaneously at each historical t.

The static feature \`bed_capacity\` is nominal capacity from a versioned topology available by D, distinct from \`open_beds\`.

## Actions: explicit, bounded and not silently oracle

Each action interval is \`[t-Δ,t]\` and must be an explicit record including true zeros, with known timestamps, a source event ID, version and availability. The action vector in \`actions_context\` is attached to the interval **ending at** the corresponding observed context time t. No missing interval can be interpreted as a zero intervention.

The source schema additionally requires an explicit \`source_system=synthetic_action_observed\` and \`synthetic_only=true\`. Labels such as \`criticality\`, hidden simulator state and extra action channels are rejected.

Future actions are NOT inferred from future realized interventions. The emitted model forward declaration is \`action_mode=no_op\`, \`future_actions=None\` and \`future_actions_available_ns=None\`. It represents an **explicit hypothetical zero-future-action scenario**, not a factual forecast under an unknown future policy.

Future observed outcomes are produced **only in the separate** \`training_targets\` field at D+H for each defined horizon, with \`training_target_mask\` indicating whether the data was observed by a later, declared label cutoff L. Missing labels get a numeric placeholder of zero **and a target mask of zero**, never a genuine observed-zero label. Those labels are **not forwarded as input observations**.

A future teacher-forced action target or known-plan simulator rollout, if useful for action-conditioned training, requires a **separate explicit training-only protocol**. The v1 adapter deliberately does not claim to generate action-conditioned counterfactual outcomes.

## Shapes and output example

For B=1, C history steps, F observable features, A=2 synthetic action channels, M targets, K prediction horizons:

| Key | Shape | Meaning |
|---|---|---|
| \`x\` | \`[1,C,F]\` | safe observations, observed-missingness flags and age |
| \`static\` | \`[1,1]\` | nominal bed capacity from topology |
| \`actions_context\` | \`[1,C,2]\` | exact known historical action intervals |
| \`origin_ns\` | \`[1]\` | decision time in UTC ns |
| \`event_ns\`, \`available_ns\` | \`[1,C]\` | as-of source event and version delivery times |
| \`training_targets\`, \`training_target_mask\` | \`[1,K,M]\` | supervision **not** part of forward input |
| \`future_actions\` | \`None\` | no future action oracle |
| \`action_mode\` | \`no_op\` | explicit no-action scenario |

The model fixture targets are \`ed_waiting\` and \`occupancy\` at hospital level. In contrast, historical WM-B0/V-D \`queue_urgent_hospital\` must not be silently substituted for \`ed_waiting\`.

## Archival format

**Observed archive:** original \`OPERATIONAL_V2_RESEARCH_1\` export:
\`\`\`
<observed_root>/manifest.json
<observed_root>/topology.json
<observed_root>/observations/hospital.jsonl.gz
\`\`\`

**Same-run synthetic action archive (proposed exporter contract; NOT already available):**
\`\`\`
<action_root>/manifest.json
<action_root>/actions/intervals.jsonl.gz
\`\`\`

The action manifest must include:
\`schema= hospitalos.synthetic_action_ledger_v1\`,
\`synthetic_only=true\`,
\`status=complete\`,
\`partition=train|development|validation\`,
\`source_manifest_sha256\`,
\`source_clock\`,
\`entity_level=hospital\`,
\`entity_id\`,
\`file=actions/intervals.jsonl.gz\`, and \`files_sha256\` of the action gzip.

Each action JSON line must carry \`schema\`, \`event_id\`, \`version\`, \`entity_id\`, \`source_system\`, \`interval_start\`, \`interval_end\`, \`recorded_at\`, \`available_at\`, \`values\` and \`synthetic_only\`. Values are an ordered object with **exactly** \`staffing_delta\`, then \`discharge_delta\`, with finite numeric values. The exporter must document alignment with underlying simulated interventions at the interval boundary. Do not reuse actions from an unrelated run.

The reader refuses \`test\`, \`holdout\`, unknown partitions, corrupt manifests, SHA mismatch, inconsistent source identities and missing action coverage. All source paths must remain inside their private archive root and are size bounded. No patient-identifiable source may enter this archive.
